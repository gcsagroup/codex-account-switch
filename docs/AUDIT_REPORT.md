# Codex Account Switch 项目审查与实施报告

审查日期：2026-08-25
审查版本：`0.1.0 - 未发布`
范围：Rust/Slint 源码、Codex 与 Claude 凭据生命周期、额度解析、并发、UI、测试和 macOS/Windows 交付链路。

## 结论

项目已经从可用原型收敛为具备本地安全边界、事务式切换、恢复能力和双平台构建链路的桌面应用。核心高风险覆盖路径已经修复，macOS 安装版完成真实界面与进程行为验证，Windows x64/x86 完成构建和静态产物校验。

当前仍不满足公开发布条件：macOS 包未签名/公证，Windows 未做真机与代码签名验收，仓库当前没有可审计的正式提交历史或 Release 基线。因此准确状态是“本地可用、工程验证通过、公开发布仍受门禁约束”。

## 审查方法

- 逐模块检查身份解析、Profile 存储、Codex/Claude 切换、登录、重启、额度缓存和 UI 绑定。
- 对危险路径检查输入校验、锁、快照、原子替换、回滚和删除恢复。
- 运行固定 Rust 1.97.1 工具链下的格式检查、Clippy 和全部测试。
- 打包并启动 `Codex Account Switch.app`，检查真实三账号、额度、重置时间、语言菜单、Claude 模式和退出行为。
- 构建 Windows x64/x86，检查 PE 架构、SHA-256 和 VC Runtime 动态依赖。

## 已完成的核心修复

### P0：凭据覆盖与事务一致性

- 浏览器登录或外部导入后统一采用 `adopt_live_profile`，新账号写入 Profile 后同步 current 标记，不覆盖原账号。
- 保存当前账号时，如果别名属于其他账号或 live 与已保存身份不一致，拒绝覆盖。
- 切换前在锁内重新验证目标 Profile；损坏、空凭据或不安全别名无法替换 live 文件。
- 切换前保存 live 恢复快照，并把当前账号刷新后的 token 写回原 Profile。
- current 标记写入失败时恢复原 live 文件；回滚失败会返回明确错误，不伪装成成功。

### P0：Claude SQLite 一致性

- 不再直接复制活动 Cookies 文件，改用 SQLite Backup API 获取一致快照。
- 保存和切换前执行 `quick_check`、cookies 表检查和 sidecar 状态处理。
- 切换前退出 Claude Desktop、写入恢复快照，失败时保留或恢复原数据库。
- Claude Profile 支持改名、私有回收区和恢复上次删除。

### P1：权限、并发与生命周期

- Unix 数据目录目标权限为 `0700`，凭据、锁和临时文件创建时即使用 `0600`。
- 使用唯一临时文件、原子替换和目录同步，避免固定 `.tmp` 文件竞争。
- 增加应用单实例锁、Codex/Claude 文件锁和额度刷新 single-flight。
- 浏览器登录支持取消与 300 秒超时，退出应用时终止仍在运行的登录子进程。
- macOS 标题栏关闭、界面退出和托盘退出统一调用退出路径，停止后台轮询并结束事件循环。

### P1：额度与活动数据

- 解析 5 小时/每周窗口的百分比、重置时间和 credits。
- 按窗口长度归类 API primary/secondary，修复 Pro 仅返回一个每周窗口时的误判。
- 过期窗口改为等待刷新，避免展示已经重置的历史百分比。
- 每个账号卡片展示额度、重置时间和最后刷新时间。
- 当前账号展示累计 Token、峰值日、连续使用、最长会话和最近七天趋势。
- 新增独立活动洞察页，展示 52 周热力图、每周/累计趋势、最长连续天数、推理强度、技能/聊天统计和常用插件/技能。
- 服务端可空插件字段按可选值解析；活动请求暂时失败时保留上次成功快照。

### P1：UI 与可用性

- 重构顶部导航、当前账号、额度卡片、导入区域、账号列表和状态栏。
- 修复 Slint 嵌套布局将账号名、套餐、邮箱、更新时间和按钮文字高度压成零的问题。
- 三个 Profile 在默认 860×720 窗口内完整显示；列表较长时使用滚动区域。
- 语言菜单、Codex/Claude 模式、活动账号高亮和高额度提醒完成真实窗口检查。
- 活动洞察的每日、每周、累计三种状态使用真实账户数据完成窗口检查，并与参考截图进行同屏视觉比对。
- 补齐七种语言的功能与状态文案，并用测试确保英语键均有对应翻译。

## 当前功能边界

- Codex 支持浏览器授权、保存当前、路径/文本/剪贴板导入、切换、重启、改名、删除和恢复。
- Claude Desktop 支持保存当前、打开客户端、切换并重启、改名、删除和恢复。
- OAuth 与 API Key 都可管理；订阅额度仅适用于有效 ChatGPT OAuth 账号。
- 系统托盘支持显示窗口、刷新、快速切换和退出。
- 项目没有远程账号服务、遥测或云同步。

## 未完成的发布门禁

1. macOS 尚未配置 Developer ID，当前 App 未签名、未公证。
2. Windows 尚未在 x64/x86 真机执行登录、切换、Claude SQLite、重启和退出验收。
3. Windows 尚未完成代码签名和 SmartScreen/杀毒误报检查。
4. 当前仓库无正式 Release，且工作树缺少可追溯的提交基线；不能仅凭本地文件宣称可复现发布。
5. ChatGPT `wham` 接口属于第三方非稳定接口，需要保留解析失败和手动刷新降级路径。

## 建议顺序

1. 建立首次可信提交、受保护主分支和 `v0.1.0` 发布候选标签。
2. 在隔离的 Windows x64 与 x86 环境完成代表性真机验收。
3. 配置 macOS Developer ID 与 Windows 代码签名证书。
4. 生成签名后的平台产物、SHA-256、发布说明和可复现实验记录。
5. 通过全部门禁后，将 `CHANGELOG.md` 中 `0.1.0 - 未发布` 改为正式发布日期。
